# 🎮 Retro Game — пошаговая игра

**Retro Game** — учебная браузерная игра на JavaScript. Игрок управляет отрядом на поле **8×8**, сражается с компьютером и развивает уцелевших персонажей при переходе на следующие уровни.

Итоговая работа по модулю **«Продвинутый JavaScript: современные возможности языка»** Нетологии. Проект основан на [учебном задании](https://github.com/netology-code/js-advanced-diploma) с готовым интерфейсом и частью базовых классов. Основная работа — игровая логика, развитие персонажей, сохранение состояния, тесты и настройка окружения.

## Функционал

- Случайное формирование двух отрядов по четыре персонажа в начале игры и размещение по разным сторонам поля.
- Шесть классов персонажей с собственными характеристиками и дальностью перемещения и атаки.
- Пошаговые перемещения и сражения: после действия игрока ход получает компьютер.
- Подсветка доступных клеток и целей, смена курсора, подсказки с характеристиками и индикаторы здоровья.
- Расчёт урона с учётом атаки и защиты, анимация попадания и удаление погибших персонажей.
- Повышение уровня выживших персонажей, восстановление здоровья и переход к следующему сражению.
- Создание нового отряда из четырёх противников со случайными уровнями от 1 до текущего уровня игры.
- Бесконечная последовательность уровней с циклической сменой четырёх тем: прерия, пустыня, Арктика и горы.
- Сохранение и загрузка игры через `localStorage`, восстановление последнего сохранения при открытии страницы.
- Начисление 10 очков за каждого побеждённого противника, учёт рекорда и вывод результата по завершении игры.
- Сообщения и ошибки в модальных окнах на основе HTML-элемента `<dialog>`.

## Управление игрой

1. Нажмите на своего персонажа — он выделится жёлтым.
2. Выберите свободную клетку с синей рамкой для перемещения или противника с красной рамкой для атаки.
3. После перемещения или атаки дождитесь ответного действия компьютера.
4. Победите всех противников, чтобы перейти на следующий уровень. Игра заканчивается, когда в вашем отряде не остаётся персонажей.

При наведении доступная клетка перемещения дополнительно выделяется зелёным, а цель атаки — красным. Подсказка над персонажем показывает его уровень, атаку, защиту и здоровье.

### Кнопки

| Кнопка | Действие |
| --- | --- |
| `New Game` | Начать новую партию с первого уровня, сохранив текущий рекорд в состоянии игры. |
| `Save Game` | Сохранить позиции, характеристики персонажей, уровень игры, очки, рекорд и состояние хода. |
| `Load Game` | Восстановить последнее сохранение. |

Сохранение выполняется вручную кнопкой `Save Game`; при перезагрузке страницы загружается именно оно. Данные хранятся в текущем браузере и не синхронизируются между устройствами. Очки и рекорд выводятся в сообщении об окончании игры.

## Технологии

| Область | Технологии и назначение |
| --- | --- |
| Игровая логика | **JavaScript**, ES-модули, классы и наследование, генераторы, `Promise`. |
| Интерфейс | **HTML5**, **CSS3**, Grid Layout, DOM API, события мыши и `<dialog>`. |
| Состояние | **localStorage**, сериализация в JSON и восстановление экземпляров классов. |
| Сборка | **Webpack 5**, webpack-dev-server, HtmlWebpackPlugin, MiniCssExtractPlugin, загрузка изображений через Asset Modules. |
| Совместимость JavaScript | **Babel**, `@babel/preset-env`, полифиллы **core-js**. |
| Проверки | **Jest**, **ESLint**, **Husky**, **GitHub Actions**. |

Игра работает на клиенте без серверного API и UI-фреймворков. Node.js и npm используются для установки зависимостей, сборки и проверок.

## Установка и запуск

Для запуска используйте **Node.js 26** и npm — эта версия Node.js указана в конфигурации CI проекта.

```bash
git clone https://github.com/potykalov/retro-game.git
cd retro-game
npm ci
npm start
```

Сервер разработки откроет игру по адресу [http://localhost:8080](http://localhost:8080). Для остановки нажмите `Ctrl + C` в терминале.

### Доступные команды

| Команда | Назначение |

### Особенности реализации

- **Разделение ответственности.** `GameController` управляет правилами игры, `GamePlay` работает с DOM, а `GameStateService` получает хранилище через конструктор.
- **Генерация команд.** Генератор `characterGenerator` выдаёт персонажей случайного типа и уровня в заданных пределах; `generateTeam` собирает из них отряд.
- **Координаты поля.** Позиции хранятся как индексы от 0 до 63. Для проверки хода и атаки индекс преобразуется в строку и столбец.
- **Ход компьютера.** Из доступных атак выбирается вариант с наибольшим уроном. На каждом пятом ходу или при отсутствии целей случайный противник пытается приблизиться к случайному персонажу игрока.
- **Развитие персонажей.** После победы выжившие получают следующий уровень и до 80 единиц здоровья, но не более 100 суммарно. Атака и защита пересчитываются с учётом здоровья до восстановления.
- **Загрузка состояния.** Данные из JSON переносятся в новые экземпляры соответствующих классов, поэтому у восстановленных персонажей сохраняются методы, включая `levelUp()`.
- **Анимация и очерёдность.** `showDamage()` возвращает `Promise`; перерисовка и продолжение хода выполняются после окончания анимации.

## Тестирование

Тесты находятся в каталогах `__tests__` рядом с проверяемыми классами и утилитами. Они охватывают:

- запрет прямого создания `Character` и начальные свойства конкретных персонажей;
- работу генератора и формирование команд;
- определение типа клетки по её положению на поле;
- формирование подсказок с характеристиками;
- подсветку и курсоры для доступных и недоступных перемещений и атак;
- успешную загрузку сохранения и обработку ошибки загрузки с моками `load` и методов интерфейса.

В [GitHub Actions](.github/workflows/node-ci.yml) настроены установка зависимостей, запуск тестов с покрытием, ESLint и production-сборка при push и pull request в `main`. Husky запускает тесты и линтер перед коммитом.
